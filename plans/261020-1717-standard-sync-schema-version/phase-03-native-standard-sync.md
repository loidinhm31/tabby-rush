## Architecture and durable state
- Transport: `push`, `pull`, `delta` POST `/api/v1/sync/{config.appId}/…`; auth classification `DUAL_AUTH_SYNC` only for these three exact paths, Bearer + `X-API-Key` + `X-App-Id`. Remove strong/bootstrap/receipt admission; reject other app IDs, suffixes, query variants, absolute/foreign URLs and redirects. Existing auth/announcements allowlists remain unchanged.
- DTOs mirror actual Rust camelCase shapes, including `deleted`, `syncedAt`, `hasMore`, `{updatedAt,id}` checkpoints and nested delta results; push/pull each carry positive exact `schemaVersion`. Persist raw `JsonObject` data, not decode/re-encode through a closed DTO. Tombstones need no live-task decode.
- Room4 separates `hubSchemaVersion`, confirmed per-record version, local intent revision and string timestamp checkpoint. Persist scan generation/state/checkpoint, last completed catch-up time, opaque base/staging JSON, projection/review state and immutable dispatch envelopes. Never use `serverTimestamp`, task deadline/createdAt or local wall-clock as pull cursor.
- Observe Hub counter monotonically across responses; delta's nested snapshots may differ. Counter observation neither migrates Room nor enables/disables native features. Missing/invalid response metadata fails safely without erasing intent; schema validation errors retain a recoverable draft and actionable sync status.
- Standard outbox: per-row FIFO; one eligible head per `(tableName,rowId)`. Envelope captures local revision, known-field intent mask, raw full payload, deleted flag, `version > confirmedVersion`, explicit `assumedServerVersion` (0 for truly new rows), dispatch status/history. Freeze envelope before network I/O; reject version exhaustion rather than wrap.
- Legacy evidence: archive every old outbox row losslessly, including protocol, op ID, epoch, digest, revisions, payload, provenance, history and state. Keep migration readers/evidence only; no old network implementation, digest recomputation or compatibility aliases. Preserve old base/drafts/settings/reminder ledger and their local visibility while standard scan is pending.
- Data merge: derive each new full-record write from latest raw confirmed base plus only captured locally changed known fields, including explicit nulls; retain opaque keys/nested values exactly as JSON values through conflict reapply/restart. Never synthesize new required fields or copy a stale typed row over raw remote data. New-row payloads contain current known task fields only.
- Scheduling/projection: raw incompatible data remains recoverable with a projection error; never schedule it as a valid task. Local deletion/preservation barriers overlay remote projection; known-deleted/missing parents suppress child visibility/scheduling or enter recovery, rather than produce orphan alarms.

## Numbered implementation steps
1. Freeze Kotlin shapes against phase02's actual protocol and baseline counter behavior. Replace strict DTO/client methods in place with standard push/pull/delta; remove bootstrap, epoch admission, receipt fetch and exact fingerprint/version checks. Add method/path tests; never broaden dual auth to `/sync/*`.
2. Implement explicit `MIGRATION_3_4` and register complete 1→2→3→4 chain in both builders. Transactionally copy old outbox to lossless JSON evidence (Kotlin serialization over SQLite rows; no reliance on optional SQLite JSON functions), rebuild active outbox for standard envelopes, migrate typed base/drafts and metadata, add raw/staging/checkpoint/review columns, retain preferences and delivery ledger. Do not mark old strict base standard-confirmed or discard draft/task fields. No destructive fallback, wipe, reinstall or network inside migration.
3. Make migration restart-safe with durable per-evidence translation outcome/source ID and unique linkage; new edits made during scanning are local intents, never overwritten at promotion. Keep migration-era typed base until full standard promotion; raw reconstructed known fields are not proof of a fresh remote base.
4. Implement initial/resumption staged standard pull from null checkpoint filtered to `todos`. Each validated page + its returned checkpoint + observed Hub version commits atomically; crash before commit re-fetches page, crash after commit resumes. Drain `hasMore`, including an extra empty final page; preserve exact timestamp precision/tie IDs and reject nonprogressing pagination safely.
5. Promote only completed scan generation atomically with metadata; normal incremental pages update raw base, typed projection, conflict inputs and checkpoint in one transaction. Keep local overlays. Standard pull is not a frozen strict snapshot: process intervening updates through catch-up, preserve row versions and avoid regressing newer bases. Malformed known fields retain raw review evidence; no silent coercion/scheduling or partial-page cursor advance.
6. Translate **provably never-dispatched** legacy intent only after fresh base: trusted history + state + intent mask must establish non-delivery; absent/ambiguous history (especially Room1), DISPATCHING/UNCERTAIN/superseded work enters review. Reapply only changed fields over fresh raw base. Create only if genuinely never-confirmed, never-sent create and absent after complete scan; absent update/delete is not an upsert. Preserve delete/last-child intent. Unknown masks require review; translation is idempotent and never emits a strict packet.
7. Build FIFO selection and immutable dispatch persistence; parent must be confirmed live before first child dispatch. Start ordinary incremental rounds with reconciled state, preferably delta containing eligible push + first pull; drain remaining pulls separately. Persist push acknowledgement and pull outcome independently: partial delta/transport failure does not imply atomic rollback or successful delivery.
8. Apply only explicit accepted `(tableName,rowId,version)` matching a frozen in-flight envelope and captured local revision; atomically update base/evidence and retire that exact entry. Ignore unexpected/duplicate/old acknowledgements; never clear by aggregate `synced`, missing failure, successful HTTP or table-wide operation. Preserve newer queued edit, rebase its unsent changed fields over accepted raw base, and unblock only the next head. Failures/conflicts remain durable.
9. On timeout/cancellation/dropped or unparsable response, persist uncertain delivery; auth refresh may return retry-needed but must not resend POST automatically. Pull/reconcile before another write. Matching remote version/full JSON/deleted state establishes **desired-state convergence**, not an operation receipt; record that distinction. Newer/divergent/missing remote state is reviewable; never blindly raise version, overwrite or recreate an uncertain row. Resolve ordinary conflicts by refreshed remote base and explicit reapply/discard/copy-as-new actions; reapply mints a new envelope and preserves unknown fields.
10. Before replay after retention-length gap, restart full scan from null; use last completed catch-up time, not last successful push. Current generic horizon is 60 days only when deployment supplies a trustworthy bound; default to full scan before reconnect replay if unknown, changed or clock evidence is unsafe. Completed-scan absence of previously confirmed rows becomes deleted/review local state, missing uncertain rows review; never infer absence from partial scans or resurrect either. Retain local suppression evidence after server tombstone cleanup.
11. Preserve local hierarchy invariants: roots/children only, no self/reparent/grandchildren; derived parent completion/read-only checkbox; atomic local group delete and last-child captured completion; scheduling barriers, parent-first creation and late-child suppression/individual cleanup deletes. Generic server has no group transaction/hierarchy guard: expose partial/conflicted cleanup and retry by ordinary row rules, without claiming permanent server enforcement. Unresolved/deleted-parent children never schedule; copy-as-new explicitly creates a new root ID.
12. Preserve absolute own deadlines/no inheritance, reminder occurrence ledger/scheduleToken, widget/sticky grouping, generation/account/surface-token fences, account leave/wipe safeguards and cold restart. Wire Android factory/worker/view-model and Desktop runtime/scheduler/controller to standard coordinator. Remove `isAccountV2/V3` fields, store methods, editor/list branches and strict upgrade warnings at every caller; retain local feature validation and permission/runtime capability gates only.
13. Move SHA-256 implementation with unchanged AccountKey/announcement vectors and move ordinary task constraints from strict contracts; migrate all references before removal. Delete obsolete strict network/state/digest/receipt tests and fixtures with no remaining migration reader; preserve behavioral hierarchy/deadline/reminder/security tests. Before handoff, trace all affected constructors/callers using references/search, not compatibility aliases. Leave D scripts/docs cleanup to phase05 with exact obsolete-reference handoff.

## Conflict prevention, risks and security
- One owner integrates generated Room4 schema; preserve 1–3 as migration inputs. Phase02 owns Rust/wire generation and conversion, phase04 admin, phase05 scripts/docs/rollout; never edit their files. Block replay on strict-mode rejection before server publication; retain offline edits without switching transports.
- Main risks: falsely treating legacy PENDING as unsent; losing unknown JSON in full writes; assuming delta/group/scan atomicity; acknowledging a newer edit; retention resurrection; scheduling orphan/stale data. Durable provenance, intent masks, explicit tuples, complete-scan boundaries and behavior tests above mitigate; do not rebuild strict guarantees in standard Hub.
- Credentials stay in protected vault/session; no admin schema permissions for native users, secret logging, relaxed HTTPS/release origin policy, auth replay or cross-account raw/evidence access. Review/archive cleanup follows account wipe lifecycle; no new automatic destructive cleanup.
